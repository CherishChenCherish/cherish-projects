Gold Monitor

Solo project · Mar 2026 – now

Overview

A real-time signal system for XAUUSD (gold). Each signal passes through scoring, memory recall and an adversarial check before it reaches me, and every closed trade is reviewed and written back so the next similar setup can draw on it.

Pipeline

Price feed ↓ Multi-factor scoring ↓ Market regime detection ↓ Memory recall → BM25 over past signals and their outcomes ↓ Critic → rules + LLM argue against the trade ↓ Risk gate ↓ Alert → trade → post-trade review ↓ Review written back to memory

Why this shape

  • Memory: a signal is judged alongside how similar past signals played out, not in isolation
  • Critic: a dedicated step whose only job is to find reasons not to take the trade
  • Reflection: post-trade reviews close the loop, so the memory grows from real outcomes

Tech Stack

Python, FastAPI, WebSocket, BM25 retrieval, LLM critic, 17 modules

Live Assistant

Beta — Core complete

Overview

Listens to an interview through the microphone, detects when a question has been asked, and streams a suggested answer to the screen. Under 8 seconds from the end of the question to the first visible token.

Architecture

Microphone (sounddevice, 16kHz, 4s chunks) ↓ faster-whisper (CPU, int8 quantized) ↓ QuestionDetector │ Stage 1: 45+ heuristic patterns (instant) │ Stage 2: LLM verify (weak signals only) ↓ Responder → Ollama HTTP streaming API │ • Behavioral: 3–4 sentence spoken answer │ • Technical: verbal + code + explanation ↓ asyncio.Queue → WebSocket (50ms poll) ↓ Frontend: token-by-token streaming display

Features

Transcription

Whisper with VAD filtering. System audio via BlackHole for video calls.

Question detection

45+ patterns with preamble extraction. Strong matches skip the LLM check, about 5s faster.

Streaming

Token-by-token through the Ollama streaming API.

Follow-ups

Predicts likely next questions and prepares keyword talking points in the background.

Your context

Upload a resume, JD or notes; answers draw on your own background.

Meeting detection

Detects Zoom, Teams, WeMeet and Google Meet and suggests the right audio device.

Key Decisions

  • Thread-safe WS bridge: background threads use asyncio.Queue.put_nowait() → async consumer → ws.send()
  • HTTP API over subprocess: saves 2–3s per Ollama call and enables streaming
  • 350-char answer cap: has to be readable in about 5 seconds mid-interview
  • Warmup on startup: a 1-token ping loads the model before the first real question

Tech Stack

Python, FastAPI, WebSocket, faster-whisper, Ollama (gemma3:4b), sounddevice, HMAC-SHA256 license system

JobPilot

Solo build · shipped Mar 2026

Overview

The hard part of job search tooling is stale data: a large share of listed jobs are already closed. JobPilot pulls jobs from Greenhouse and Lever, verifies each one is still open, and only then shows it. The Claude API handles resume parsing and job matching.

Architecture

Resume (PDF) → parser.py (PyMuPDF + Claude extraction) ↓ searcher.py → Greenhouse & Lever APIs │ Profile-aware query building │ Degree filtering (no PhD-only roles for MS) ↓ verifier.py → multi-stage verification │ 1. ATS API check │ 2. HTML signal analysis (closed / open / ambiguous) │ 3. Posting-age check │ Ambiguous → labeled "unverified", never "open" ↓ generator.py → Claude-generated cover letters ↓ Next.js frontend → Google OAuth + Stripe + dashboard

Key Decisions

  • Verification order: ATS API first, HTML signals second, posting age last. When the evidence is mixed, the job is shown as "unverified"
  • Daily refresh: a background job re-verifies cached postings and drops closed ones
  • Cover letters: a banned-phrase list keeps generic filler ("passionate about", "fast learner") out of the output

Tech Stack

Next.js, TypeScript, Tailwind CSS, Flask, SQLAlchemy, PostgreSQL, Claude API, Stripe, Google OAuth (NextAuth), PyMuPDF
